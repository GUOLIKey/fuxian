# Round 7 FedVaDE controlled search

The author source and supplied weight remain read only. Every new run copies the four author Python files and Breast Cancer CSV into a new server run directory. The copy has only observation/checkpoint hooks, a candidate learning rate, alpha, sample count, and (for the epoch arm) the already studied scheduler placement change. Model and loss code are unchanged. The author weight is never copied into a run.

Author defaults: 10 clients, batch size 200, latent 10, two Breast Cancer clusters, learning rate 0.002, alpha 0.01, 100 server samples, Adam, StepLR(step_size=10, gamma=0.85), 50 pretraining rounds and 300 formal rounds. The author client StepLR steps per mini-batch. Preprocessing fits StandardScaler on all 569 rows; the 10 seeded non-IID client partitions contain 2129 records. Seed 0 fixes Python, NumPy and PyTorch CPU RNG; partition and GMM fitting use seed 42 in author code. CUDA is not used, matching prior CPU runs. The source has no validation split or best-checkpoint selection.

Coarse search has 16 configurations at 50+150 rounds: author and epoch scheduler baselines at LR 0.002/alpha 0.01; LR 0.0005/0.001/0.005 at alpha 0.01 under each scheduler; alpha 0.001/0.005/0.05 at LR 0.002 under each scheduler; and LR 0.001/alpha 0.005 under each scheduler. Sample count stays 100. The author baseline at epoch 150 reuses the existing Round 5 A checkpoint rather than retraining; 15 coarse runs are new.

Fine search selects the top four coarse configurations by **fixed epoch 150** author-protocol ARI mean over ten inference seeds. Thus four fine candidate configurations are evaluated at 50+300 rounds; existing full 300-round baseline checkpoints are reused when applicable. Server sample count stays 100 because it also affects pretraining GMM construction in the author's code, so a simple sample-count change would confound two stages. No more than 19 new training runs are scheduled. There is no adaptive addition of more parameters or training rounds.

All checkpoint comparisons use the Round 6 author-protocol evaluator and inference seeds 0-9. Training does not call ten-seed inference, so evaluation cannot change its RNG trajectory. Server snapshots are saved every 25 rounds; the final full checkpoint saves server, clients, optimizers, schedulers and RNG. `best_checkpoint.pt` is chosen **within a run** by minimum trailing-five client training loss among saved epochs and uses no evaluation labels. `best_exploratory_ari_checkpoint.pt` is selected by ARI and is **label-selected exploration only**. Choosing fine configurations by ARI on the same client records is also exploratory. None of these ARI-selected scores is an unbiased independent test result. The full-data scaler, ID input, label-assisted partition/GMM component count and repeated client records remain author-protocol caveats.
